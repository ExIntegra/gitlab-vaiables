# Генератор инфраструктуры

Откройте вкладку «Сгенерировать инфраструктуру». Добавьте группу, проекты и участников или нажмите «Пример». У каждого проекта есть раздел «Редактировать политику веток».

Эта вкладка добавлена в исходники после опубликованного образа `1.0.0`. Для запуска обновления через Docker соберите текущий код:

```powershell
docker compose -f compose.yaml -f compose.build.yaml up --build -d
```

Адрес при запуске через Compose - `http://localhost:8081`.

## Формат

Генератор использует общую переменную `infrastructure` из `ExIntegra/terraform-gitlab`, обсуждённую в чатах «Изучить репозиторий Terraform» и «Refactor Terraform GitLab modules». Пример файла `terraform.tfvars.json`:

```json
{
  "infrastructure": {
    "backend": {
      "parent_group": "company",
      "description": "Команда backend",
      "visibility_level": "private",
      "members": {
        "ivan": "maintainer",
        "anna": "developer"
      },
      "projects": {
        "api": {
          "description": "Backend API",
          "visibility_level": "private",
          "initialize_with_readme": true,
          "default_branch": "main",
          "merge_method": "merge",
          "protected_branches": {
            "main": {
              "push_access_level": "no one",
              "merge_access_level": "maintainer",
              "allow_force_push": false
            }
          }
        }
      }
    }
  }
}
```

Имя группы и проекта - одновременно их путь в GitLab. Родительская группа задаётся полным путём и уже должна существовать. Пустой родительский путь создаёт группу на верхнем уровне; разрешения проверяет GitLab при применении. Для участников указываются существующие username. Участники добавляются в группу, доступ к проектам наследуется.

Видимость: `private`, `internal`, `public` (доступность internal зависит от экземпляра GitLab). Роли: `guest`, `reporter`, `developer`, `maintainer`, `owner`. Методы слияния: `merge`, `rebase_merge`, `ff`. В проекте без начального README основная ветка не экспортируется. Правила защиты могут содержать шаблон `release/*`, но сами ветки не создают.

Пустые и повторяющиеся имена, повторные участники в одной группе, некорректные роли и противоречивый force push блокируют скачивание. Проекты с одним именем допустимы в разных группах. Один комплект ограничен 25 группами, 250 проектами и 1000 назначениями участников; запрос - 128 КБ.

## Использование в Terrakube

Есть два способа передать входные данные:

1. Скачать `terraform.tfvars.json` и добавить файл в корень Terraform-репозитория workspace.
2. Выбрать формат «Для Terrakube», скопировать объект, создать Terraform-переменную с ключом `infrastructure` и включённым HCL. В этом режиме внешний объект `{"infrastructure": ...}` не нужен. Литеральные `${` и `%{` в текстовых полях экранируются для HCL автоматически.

Используйте один источник входных значений: файл или переменную workspace. Дублирующее значение из другого источника может его перекрыть.

Формат «Для Terraform без Terrakube» выдаёт файл `terraform.tfvars.json`. В разделе «Модули Terraform для защиты веток» кнопка «Скачать модули Terraform» выдаёт ZIP с входным JSON, адресом GitLab и тремя модулями: `create_gitlab_group`, `create_gitlab_project`, `add_members_in_group`. Она нужна, если в ваших модулях ещё нет поддержки `protected_branches`; в комплекте эти правила уже реализованы. Провайдер закреплён на `gitlabhq/gitlab` 18.0.0, минимальная версия Terraform - 1.3; проверено на 1.12.2 Windows x64. Для нового workspace добавьте весь комплект в репозиторий, задайте чувствительную переменную окружения `TF_VAR_gitlab_token`, затем выполните Init, Validate и Plan. Apply выполняйте после проверки плана.

В исходной версии модулей есть основная ветка и метод слияния, но нет `protected_branches`. Старые типизированные объекты Terraform отбрасывают неизвестные поля, поэтому одно добавление JSON не включает защиту веток. Используйте комплект или перенесите поле и ресурс защиты в существующий модуль проектов. Существующая инфраструктура и Terraform state требуют отдельной проверки перед заменой модулей или переходом с провайдера 3.18 на 18.0.0; генератор не выполняет import или миграцию.

## Загрузка JSON и безопасность

«Загрузить JSON» принимает `terraform.tfvars.json` с внешним ключом `infrastructure` либо объект из значения переменной Terrakube. HCL-файлы `.tfvars` не импортируются. Неизвестные поля отклоняются, чтобы настройки не пропадали незаметно. Импорт или загрузку примера поверх заполненного черновика можно отменить ссылкой «Отменить замену черновика».

Черновик, предварительный просмотр и архив находятся в памяти страницы; в localStorage и файлы сервера они не записываются. При выходе данные очищаются. Экспорт не содержит токена сессии или значений CI/CD-переменных. API генерации требует сессию, корректный Origin и CSRF-токен и не обращается к GitLab или процессу Terraform.

Источники: [формат входных переменных Terraform](https://developer.hashicorp.com/terraform/language/values/variables), [переменные Terrakube и HCL](https://docs.terrakube.io/user-guide/workspaces/variables), [защита веток в провайдере 18.0.0](https://github.com/gitlabhq/terraform-provider-gitlab/blob/v18.0.0/docs/resources/branch_protection.md).
